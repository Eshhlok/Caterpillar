# Smart Operator Assistant

A simulated Caterpillar heavy-equipment operator dashboard with a mascot
co-pilot, pre-start safety checks, terrain awareness, and environmental
(gas/O2/pressure) monitoring. All sensor data is generated by an in-memory
simulator — no real IoT hardware required.

This project was scaffolded on Replit and has been de-Replit-ified so it
runs on any machine with Node.js + pnpm.

## Project structure

```
artifacts/
  smart-operator-assistant/   # React + Vite frontend (the dashboard UI)
  api-server/                 # Express API + in-memory sensor simulator
lib/
  api-spec/                   # OpenAPI spec the client/server types are generated from
  api-zod/                    # Generated Zod schemas (shared types)
  api-client-react/           # Generated React Query API client
```

The frontend talks to the backend over `/api/...` relative paths. In dev,
Vite proxies `/api` to the API server (see `server.proxy` in
`artifacts/smart-operator-assistant/vite.config.ts`) so both run on their
own ports without needing a shared router the way they did on Replit.

## Requirements

- Node.js 20+ (Node 24 is what the original Replit env used)
- pnpm (`npm install -g pnpm` if you don't have it)

## Setup

```bash
pnpm install
pnpm dev
```

This starts both services at once:

- API server → http://localhost:8080 (health check at `/api/healthz`)
- Frontend → http://localhost:5173

Open **http://localhost:5173** — that's the dashboard. You don't need to
open the API port directly; the frontend proxies to it.

To run them separately instead (e.g. in two terminals):

```bash
pnpm --filter @workspace/api-server run dev
pnpm --filter @workspace/smart-operator-assistant run dev
```

## Ports

Both ports have local defaults baked in (`8080` for the API, `5173` for the
frontend), so you don't need to set any environment variables to get
started. If you want to override them:

```bash
PORT=9090 pnpm --filter @workspace/api-server run dev
API_PORT=9090 PORT=3000 pnpm --filter @workspace/smart-operator-assistant run dev
```

(`API_PORT` tells the frontend's dev-server proxy where to find the API;
`PORT` sets the port each service itself listens on.)

## What changed from the Replit export

- Removed `.replit`, `.replitignore`, `.agents/`, `.conversation/`,
  `replit.md`, and the `mockup-sandbox` artifact (all Replit-tooling-only).
- Removed the unused `lib/db` workspace package and its dependency in the
  API server — nothing in the app actually queried a database.
- Removed the `@replit/vite-plugin-*` dev dependencies and the
  `@replit/connectors-sdk` root dependency.
- `vite.config.ts` and the API server no longer hard-require `PORT` /
  `BASE_PATH` env vars — they default to sensible local values.
- Added a dev proxy (`/api` → API server) so the two services can talk to
  each other locally, replacing the path-based routing Replit provided.
- Added a root `pnpm dev` script (via `concurrently`) to start both
  services with one command.

## Building for production

```bash
pnpm build
```

This type-checks the workspace and builds each app
(`artifacts/*/dist`). You'd serve the built frontend as static files and
run the built API server (`node artifacts/api-server/dist/index.mjs`)
behind whatever reverse proxy or hosting setup you choose, pointing it at
the frontend build's `/api` calls.
